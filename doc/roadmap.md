# 路线图（草案）

> 2026-10-23 修订：采用 PCL-Harmony 的跨启动器插件契约；CE 不再放最后，与官方版、开源版一起按"尝试性 hook"推进；CurseForge Key 的取得顺序与开发顺序已定。

## 目标

给 PCL 做一个基于 PCL-Harmony 的增强 Mod：

1. **去云控和遥测**（见下文）。
2. **去除对 MC 下载的限制。**
3. **为开源版补全正版（微软）登录。**
4. **换用 CurseForge 官方启动器的 Key，补全搜索与下载。**

支持对象：官方闭源版、开源 Meloong 版、PCL-CE。官方 / 开源版的支持范围是 `2.99.0.0` 及更新版本；不支持的版本进入安全模式（见 [architecture.md](architecture.md)）。不再按版本分流，而是尝试性 hook：hook 不上，就禁用对应功能并提示用户。

## 云控的含义

- 完全去除所有云控：PCL 正常情况下只能外连众所周知的服务（镜像源、Modrinth、CurseForge、微软与 Mojang 等），不能连接其他服务，例如 PCL 自己的云控、遥测、更新服务器。
- 动机是有人担心 PCL 里藏有后门（加密 socket、直连 IP）。目标是**尽可能防止**，不是正式审计，也不追求证明没有后门。
- 分两层：
  1. **功能级安静停用**：对每个依赖云控的功能不再发请求，界面处置灰并提示"因禁用云控而失效"，不让 PCL 一直报错。
  2. **外连防护（兜底）**：拦下白名单以外的连接，只记日志并提示一次，不弹错误框。
- 提供总开关：用户可以关闭"禁用云控"，PCL 恢复原样。先做成配置文件项（重启生效），界面内的开关放在后面。
- 更新服务器不在白名单内，更新入口一并安静停用。
- 契约能否对 .NET 自带类型打补丁尚未核实，核实后再决定防护深度。

## 各功能

| 功能 | 说明 |
|---|---|
| 去云控与遥测 | 官方版：云控入口、遥测、更新等逐项停用；开源版：源码已置空，主要做确认与兜底；CE：对应其自己的联网点 |
| 去下载限制 | 官方 / 开源版约 6 处调用点（`RestrictMcDownload` 是编译期常量，只能逐处处理）；CE 有基于地区的限制，目标点不同 |
| 正版登录 | 只给开源版：官方版本来就有，CE 已有设备码登录 |
| CurseForge 官方 Key | 官方版、开源版、CE 都做；接入点倾向于对 `SecretHeadersSign` 做后置补丁（CE 对应位置待查） |

### 正版登录

- 借用官方启动器的 Client ID（公开标识，写成常量，与 Modrinth App 一致）。
- 该 ID 是旧式 live.com 应用：对 PCL 现有的 Azure AD 设备码接口会被拒绝，对 live.com 旧式设备码接口可用。因此要改登录步骤 1（设备码请求、弹窗里轮询令牌的代码、刷新登录的授权范围）和步骤 2（`RpsTicket` 前缀）。
- 后续步骤能否被 Mojang 接受没有验证，需要用户亲自登录一次测试；若被拒，再退到 Modrinth 的 Sisu 流程。
- 目前暂停。

### CurseForge Key

- 仓库里不存放 Key 的值。
- **取得顺序（实际使用）**：① 读本机已安装的官方启动器 → ② 照 Fjord 的做法联网取得 → ③ 用户手动填写。
- **开发顺序**：② → ① → ③。
- ② 沿用 Fjord 的现有逻辑，不为 Windows 另做改造；失败时告诉用户可能的原因，不让用户一头雾水。
- 联网取得会经过外连防护，所以相关主机要放进白名单。

## 步骤顺序

每一步都小到可以逐行审核；每步完成后给出审核清单，经确认再进入下一步。

1. **骨架与加载验证**：建好工程，做一个只写日志的最小插件（`IDeclarativePlugin`），在我们自编的开源版上用 Harmony 加载。第一次真正运行，需要隔离环境，先给方案、经同意再运行。
2. **尝试性 hook 框架、版本门禁与安全模式、配置文件、日志。**
3. **外连白名单与功能级停用**（原"去云控"）。
4. **去下载限制。**
5. **CurseForge 官方 Key**（按 ② → ① → ③）。
6. **正版登录**（开源版）。
7. **CE 的适配与验证**：补丁目标与官方版不同，要单独核对。
8. **打包、安装说明与发布。**

## 进行中的调查

- 闭源版联网地址与云控功能到界面的映射（给白名单与置灰提供依据）。

## 待核实 / 待定

- 契约是否能对 .NET 自带类型（如 `HttpClient`）打补丁。
- CE 的支持范围怎么界定（其版本号体系与官方版不同）。
- `Core` 与 `Plugin` 是否合成一个 DLL。
- 给 Harmony 作者的改进建议暂不提，等以后再说。
- 仓库对外发布前，再确认 PCL 许可证要求（署名、公开源码、名称等）是否都已满足。
