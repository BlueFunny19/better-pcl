# 路线图（草案）

> 状态：2026-10-23 草案。PCL-Harmony 刚在 2026-10-22 增加了对 PCL-CE 的支持和跨启动器插件契约，这会影响下面的分层与顺序，调查完成后需要回头修订。

## 目标

给 PCL 做一个基于 PCL-Harmony 的增强 Mod：

1. **去云控和遥测**（见下文"云控的含义"）。
2. **去除对 MC 下载的限制。**
3. **为开源版补全正版（微软）登录。**
4. **为开源版与闭源版换用 CurseForge 官方启动器的 Key，补全搜索与下载。**

目标版本：PCL `2.99.0.0` 及更新版本；其他版本一律标记为不支持。支持对象：官方闭源版、开源 Meloong 版、PCL-CE（CE 是否放到最后见"待定"）。

## 云控的含义

- 完全去除所有云控：PCL 正常情况下只能外连众所周知的服务（镜像源、Modrinth、CurseForge、微软与 Mojang 等），不能连接其他服务，例如 PCL 自己的云控、遥测、更新服务器。
- 动机是有人担心 PCL 里藏有后门（加密 socket、直连 IP）。目标是**尽可能防止**，不是正式审计，也不追求证明没有后门。
- 分两层：
  1. **功能级安静停用**：对每个依赖云控的功能不再发请求，界面处置灰并提示"因禁用云控而失效"，不让 PCL 一直报错。
  2. **外连防护（兜底）**：拦下白名单以外的连接，只记日志并提示一次，不弹错误框。
- 提供总开关：用户可以关闭"禁用云控"，PCL 恢复原样。先做成配置文件项（重启生效），界面内的开关放在后面。
- 更新服务器不在白名单内，更新入口一并安静停用。

## 各功能与版本

| 功能 | 开源版 | 闭源版 | CE |
|---|---|---|---|
| 去云控与遥测 | 源码已置空，主要做确认与兜底 | 云控入口、遥测、更新等逐项停用 | 待定 |
| 去下载限制 | 约 6 处调用点（`RestrictMcDownload` 是编译期常量，只能逐处处理） | 同左 | 待定 |
| 正版登录 | 需要改登录步骤（只给 Client ID 赋值行不通，见下） | 官方已有，不做 | 待定 |
| CurseForge 官方 Key | 换 Key | 换 Key | 待定 |

### 正版登录

- 借用官方启动器的 Client ID（公开标识，写成常量，与 Modrinth App 一致）。
- 该 ID 是旧式 live.com 应用：对 PCL 现有的 Azure AD 设备码接口会被拒绝，对 live.com 旧式设备码接口可用。因此要改登录步骤 1（设备码请求、弹窗里轮询令牌的代码、刷新登录的授权范围）和步骤 2（`RpsTicket` 前缀）。
- 后续步骤能否被 Mojang 接受没有验证，需要用户亲自登录一次测试；若被拒，再退到 Modrinth 的 Sisu 流程。
- 目前暂停，等整体规划确认后再做。

### CurseForge Key

- 不在仓库里存放 Key 的值；参照 Fjord，运行时取得并缓存在用户本机，保留手动覆盖。
- 开源版与闭源版统一用一个"官方 Key 提供器"；接入点倾向于对 `SecretHeadersSign` 做 Postfix 覆盖请求头（待调查确认）。

## 步骤顺序

每一步都小到可以逐行审核；每步完成后给出审核清单，经确认再进入下一步。

1. **骨架与加载验证**：建好工程，做一个只写日志的最小插件，在我们自编的开源版上用 Harmony 加载。第一次真正运行，需要隔离环境（把 `APPDATA` 等指到实验目录），先给方案、经同意再运行。
2. **版本检查、配置文件、日志。**
3. **外连白名单与功能级停用**（原"去云控"）。
4. **去下载限制**（开源版与闭源版）。
5. **CurseForge 官方 Key**。
6. **正版登录**（开源版）。
7. **打包、安装说明与发布。**
8. **CE**（视 Harmony 的新支持而定）。

## 进行中的调查

- 闭源版联网地址与云控功能到界面的映射（给白名单与置灰提供依据）。
- 官方 CurseForge Key 在 Windows 上的取得方式与接入点。
- PCL-Harmony 对 CE 的新支持与新契约，对我们分层设计的影响。

## 待定

- 是否直接采用 Harmony 的跨启动器契约，替代我们自己的 Core/Host 分层。
- CE 是否仍然放到最后。
- 界面内的总开关何时做。
- 仓库对外发布前，再确认 PCL 许可证要求（署名、公开源码、名称等）是否都已满足。
